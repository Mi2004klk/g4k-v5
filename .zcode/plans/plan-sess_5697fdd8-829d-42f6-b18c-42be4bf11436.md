## Architecture decisions baked into the doc (decided by your stated stack)

- **No Redis.** Postgres-only. → Cache/Session/Queue all use the `database` driver (shared across Cloud Run instances).
- **Reverb = its own Cloud Run service**, pinned to **1 instance** (`min=1, max=1`) to avoid needing Redis pubsub. Redis-based horizontal scaling documented as the scale path only.
- **Queue worker + Scheduler = Cloud Run Jobs** triggered by **Cloud Scheduler** (queue Job every ~3 min runs `queue:work --max-time=900 --max-jobs=200` then exits; scheduler Job every minute runs `schedule:run`). No in-container `&` loops.
- **API = Cloud Run service**, `min-instances=1`, `concurrency=10`, Octane PID 1 on `$PORT`, migrations run at container start (idempotent).
- **Storage = Supabase S3** via a properly-defined `supabase` disk; `FILESYSTEM_DISK=s3`.
