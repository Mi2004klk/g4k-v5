# Phase 9 — Reports & Exports

## What
A reporting module that aggregates the data produced by attendance (Phase 5) and projects/tasks (Phase 7) into four report families — attendance reports, project completion reports, task completion statistics, and employee productivity summaries — each available in a full Admin scope and a team-limited HR scope; exported to Excel and PDF via queued jobs; surfaced through saved report views with the shared filter bar over virtualized large datasets; and topped by a weekly summary report auto-emailed to the Admin every Sunday via the Laravel scheduler. Implements R9.1–R9.8.

## Why
Reports are where attendance, project, and task data turn into decisions: which employees are late, which projects are slipping, how task throughput trends. Because the underlying data already exists after Phases 5 and 7, this phase is mostly read-only aggregation plus export and distribution — no new operational tables to write. The hard constraints are scale (a year of attendance rows for every employee is a large dataset) and responsiveness, so heavy aggregation and document generation are offloaded to the queue (project §28 — avoid long-running PHP requests), the dataset is virtualized on the client, and the weekly admin digest runs on the scheduler rather than on demand.

## Scope
- Attendance reports filterable by date range, department, and individual (R9.1).
- Project completion reports showing team, tasks done, time spent, completion date, and approval result (R9.2).
- Task completion statistics: counts and rates by status, priority, assignee, project, and date range (R9.3).
- Employee productivity summary: per-employee attendance hours, overtime, task throughput, and project contributions for a scope (R9.4).
- HR-limited versions of all four reports scoped to the employees/projects HR manages (R9.5).
- Export any report to Excel (tabular) and PDF (R9.6), generated by queued jobs.
- Weekly summary report auto-emailed to the Admin every Sunday via the scheduler (R9.7).
- Saved report views; the shared filter/sort bar across reports; virtualized rendering of large datasets (R9.8, R11.5).
- Capability gates: `reports.view-admin` (Super Admin, company-wide) and `reports.view-hr-limited` (HR, own team only).

## Non-goals
- New operational data capture — reports read existing attendance/project/task rows; no new attendance or project tables.
- Realtime report push (Reverb) — reports are pulled/exported, not broadcast; the weekly email is the only push.
- Ad-hoc SQL / report-builder UI (drag-and-drop fields, custom joins) — M1 ships four fixed report families with filters; a general report designer is deferred.
- Payroll or cost computation woven into productivity (future milestone).
- Dashboards (Phase 4 already exposes the live metric widgets); reports are deep, exportable, history-oriented views.
- Cross-module report scheduling beyond the weekly Admin email (per-employee or per-team scheduled reports are deferred).

## Phase / capability
Phase 9 of 11 · capability `reporting` · depends on Phase 5 (attendance data + the attendance Excel export this phase generalizes) and Phase 7 (project/task data + saved-views pattern). Implements R9.1–R9.8.

## ADRs
